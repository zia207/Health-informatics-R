Health Informatics in R · Part III: Privacy, Text & Applied Informatics · Module 9 of 16

Health data is among the most sensitive data there is, and its use is governed by law. Before data can be shared for research or analytics, protected health information (PHI) usually has to be removed. This module covers the HIPAA de-identification standards and implements de-identification for both structured tables and free text.

Learning objectives

By the end of this module you will be able to:

  1. Distinguish HIPAA Safe Harbor (the 18 identifiers) from Expert Determination.
  2. De-identify structured data by suppressing, generalizing, and hashing identifiers.
  3. De-identify free text using regex plus rule-based named-entity matching.
  4. Measure k-anonymity over quasi-identifiers and generalize to reach a target k.
  5. Explain synthetic data and governance controls (IRB, DUA, minimum necessary).

Ethics note. All names, MRNs, dates, and contacts in this notebook are fabricated. De-identification is safety-critical: the methods here are educational, and production systems should use validated tooling and expert review.

Dataset

The synthetic EHR plus two fabricated clinical notes seeded with PHI-shaped tokens (names, MRNs, dates, phone, email, address) so the de-identification code has realistic targets.

    given_name = sample(first, size = n_patients, replace = TRUE),

    sex = sample(c("male", "female"), size = n_patients, replace = TRUE, prob = c(0.49, 0.51)),
    age = ages,

  )

  enc_types <- c("ambulatory", "emergency", "inpatient", "wellness")
  enc_rows <- list()

    n_enc <- sample(1:4, 1)
    for (i in seq_len(n_enc)) {
      day <- sample(0:(365 * 3 - 1), 1)
      enc_rows[[length(enc_rows) + 1]] <- tibble(
        encounter_id = sprintf("E%05d", length(enc_rows) + 1),
        patient_id = pid,
        encounter_type = sample(enc_types, 1, prob = c(0.55, 0.15, 0.10, 0.20)),
        date = as.Date("2023-01-01") + day

  }
  encounters <- bind_rows(enc_rows)

  obs_defs <- list(
    list(name = "Body height", unit = "cm", lo = 150, hi = 195),
    list(name = "Body weight", unit = "kg", lo = 50, hi = 110),
    list(name = "Systolic blood pressure", unit = "mmHg", lo = 100, hi = 165),
    list(name = "Heart rate", unit = "/min", lo = 55, hi = 100),
    list(name = "Hemoglobin A1c", unit = "%", lo = 4.8, hi = 9.5)

  obs_rows <- list()

    e <- encounters[i, ]
    for (od in obs_defs) {
      if (runif(1) < 0.7) {
        obs_rows[[length(obs_rows) + 1]] <- tibble(
          observation_id = sprintf("O%06d", length(obs_rows) + 1),
          encounter_id = e$encounter_id,
          patient_id = e$patient_id,
          observation = od$name,
          value = round(runif(1, od$lo, od$hi), 1),
          unit = od$unit,
          date = e$date
        )
      }
    }
  }
  observations <- bind_rows(obs_rows)

  cond_pool <- c("Essential hypertension", "Type 2 diabetes mellitus", "Asthma",
                 "Acute bronchitis", "Major depressive disorder", "Osteoarthritis",
                 "Chronic kidney disease", "Anemia")
  cond_rows <- list()
  for (pid in patients$patient_id) {
    n_cond <- sample(0:3, 1)
    if (n_cond > 0) {
      cs <- sample(cond_pool, size = n_cond, replace = FALSE)
      for (c in cs) {
        cond_rows[[length(cond_rows) + 1]] <- tibble(
          condition_id = sprintf("C%05d", length(cond_rows) + 1),
          patient_id = pid, condition = c
        )
      }
    }
  }
  conditions <- bind_rows(cond_rows)

  med_pool <- c("Lisinopril", "Metformin", "Albuterol", "Atorvastatin", "Sertraline",
                "Amoxicillin", "Ibuprofen", "Hydrochlorothiazide")
  med_rows <- list()
  for (pid in patients$patient_id) {
    n_med <- sample(0:3, 1)
    if (n_med > 0) {
      ms <- sample(med_pool, size = n_med, replace = FALSE)
      for (m in ms) {
        med_rows[[length(med_rows) + 1]] <- tibble(
          medication_id = sprintf("M%05d", length(med_rows) + 1),
          patient_id = pid, medication = m
        )
      }
    }
  }
  medications <- bind_rows(med_rows)

  list(patients = patients, encounters = encounters, observations = observations,

}

9.1 The two HIPAA de-identification standards

Standard How it works Trade-off
Safe Harbor Remove 18 specific identifiers named by HIPAA regulations from all data. Straightforward, rule-based; may remove useful data along with identifiers.
Expert Determination An expert assesses and documents that the risk of re-identification is “very small,” allowing custom methods to reduce such risk. Allows more data utility and context sensitivity; requires specialized knowledge and thorough documentation.

Safe Harbor: Relies on a strict list of 18 personal identifiers (such as names, addresses smaller than state, full dates, and contact info) that must be removed to consider data de-identified. This method is relatively easy to apply and does not require specialized statistical or privacy expertise. However, it can inadvertently remove more information than strictly necessary for privacy, potentially harming research utility.

Expert Determination: Involves hiring or relying on a qualified expert in statistical and scientific methods who will identify direct and indirect identifiers in the dataset and certify that the likelihood of someone being re-identified from the data is very small. This approach allows for nuanced balancing between privacy and information loss, accommodating unique data situations, but it is more complex and requires expert oversight and documentation.

18 Safe Harbor identifiers (must be removed or generalized): names, any small-area geographic indicator (smaller than a state, e.g. city, zip code except for the initial 3 digits in some cases), all dates directly related to an individual (other than year), ages over 89, phone/fax numbers, emails, social security numbers, medical record/account/license numbers, vehicle/device identifiers, URLs, IP addresses, biometric identifiers, full-face photographs/images, and any other unique identifying code or characteristic.

9.2 De-identifying structured data

When working with structured (tabular) data, removing identifiers is a column-by-column process. Each column containing an identifier should have an appropriate de-identification strategy assigned to it. Common strategies include: - Suppress (drop): Remove the column entirely if it directly identifies a person (e.g., name). - Generalize (reduce precision): Broaden the information so it’s less specific, such as reporting age groups instead of exact ages, or using birth year instead of full birth date. - Pseudonymize (hash to a consistent token): Replace an identifier, like a patient ID, with a generated code (using a hash function and possibly a secret salt) that is stable within the dataset but cannot be used to recover the original value. This approach balances privacy protection with the need to retain useful, analyzable data.

library(digest)
patients <- ehr$patients

pseudonymize <- function(value, salt = "study-2026") {
  paste0("PT-", substr(vapply(value, function(v) digest(paste0(salt, v), algo = "sha256"), character(1)), 1, 10))
}

deid <- tibble(
  # pseudonymize the direct identifier (stable across the dataset, not reversible without salt)
  study_id = pseudonymize(patients$patient_id),
  # suppress names entirely
  # generalize: age > 89 collapses to '90+' per Safe Harbor; keep birth YEAR only
  age_group = cut(patients$age, breaks = c(0, 18, 40, 65, 89, 200),
                   labels = c("<18", "18-39", "40-64", "65-89", "90+")),
  sex = patients$sex
)

9.3 De-identifying free text

De-identifying free text is more complex than structured data because personal identifiers may appear anywhere within unstructured prose. To address this, we use a combination of: - Regular expressions (regex): These can reliably detect well-defined patterns such as Medical Record Numbers (MRNs), phone numbers, emails, dates, and similar structured strings. - Rule-based name/place matching: A small dictionary of known name and place tokens detects proper nouns (like “Ava Khan” or “Ithaca”) in natural language, standing in for a full named-entity-recognition model.

For maximum portability, the code below is entirely dependency-free — a production R pipeline for this step would typically reach for spacyr (a reticulate bridge to spaCy) or a dedicated NER package, but the rule/dictionary approach here needs no external model and always runs.

library(stringr)

PATTERNS <- list(
  MRN   = regex("\\bMRN\\s*\\d{5,}\\b", ignore_case = TRUE),
  PHONE = regex("\\b\\d{3}-\\d{3}-\\d{4}\\b"),
  EMAIL = regex("\\b[\\w.]+@[\\w.]+\\.\\w+\\b"),
  DATE  = regex("\\b\\d{1,2}/\\d{1,2}/\\d{2,4}\\b"),
  SSN   = regex("\\b\\d{3}-\\d{2}-\\d{4}\\b")
)

# Small dictionary standing in for NER: known person names and place names
# from the fabricated notes (a production system would use a trained NER model instead).
NAME_TERMS  <- c("Ava Khan", "Liam Ortiz")
PLACE_TERMS <- c("12 Elm St", "Ithaca")

find_matches <- function(text, pattern, tag) {
  m <- gregexpr(pattern, text, perl = TRUE)[[1]]
  if (m[1] == -1) return(tibble(start = integer(0), end = integer(0), tag = character(0)))
  len <- attr(m, "match.length")
  tibble(start = as.integer(m), end = as.integer(m) + len, tag = tag)
}

deidentify_text <- function(text) {
  redactions <- list()
  # 1) regex-based structured identifiers
  for (tag in names(PATTERNS)) {
    redactions[[length(redactions) + 1]] <- find_matches(text, PATTERNS[[tag]], tag)
  }
  # 2) dictionary-based names and places (stand-in for spaCy NER)
  for (nm in NAME_TERMS) {
    redactions[[length(redactions) + 1]] <- find_matches(text, fixed(nm), "PERSON")
  }
  for (pl in PLACE_TERMS) {
    redactions[[length(redactions) + 1]] <- find_matches(text, fixed(pl), "FAC")
  }
  red <- bind_rows(redactions)
  if (nrow(red) == 0) return(text)
  # apply right-to-left so offsets stay valid
  red <- red[order(-red$start), ]
  out <- text
  for (i in seq_len(nrow(red))) {
    start <- red$start[i]; end <- red$end[i]; tag <- red$tag[i]
    out <- paste0(substr(out, 1, start - 1), "[", tag, "]", substr(out, end, nchar(out)))
  }
  out
}

9.4 k-anonymity

k-anonymity is a privacy concept that addresses the risk of re-identifying individuals in a dataset, even after obvious identifiers (like names or SSNs) are removed. It recognizes that combinations of seemingly harmless features—such as age, sex, or ZIP code—can still uniquely identify people when combined. These features are known as quasi-identifiers.

A dataset is considered k-anonymous if every unique combination of quasi-identifiers appears in at least k different records. This means each individual is hidden in a crowd of at least k people sharing the same quasi-identifier values. The higher the value of k, the stronger the privacy guarantee: it’s harder to pick out an individual from the group.

Achieving k-anonymity often requires generalizing or coarsening the data (for example, grouping ages into ranges, or truncating ZIP codes) so that more records look alike, increasing the minimum group size. The following sections show how to measure and improve k-anonymity using real and generalized data.

Removing direct identifiers isn’t enough: quasi-identifiers (age, sex, ZIP) can re-identify people by combination. A dataset is k-anonymous if every combination of quasi-identifiers is shared by at least k records. We measure it, then generalize to raise the minimum k.

set.seed(1)
qi <- ehr$patients[, c("age", "sex")]
qi$zip3 <- sample(c("148", "149", "130"), size = nrow(qi), replace = TRUE)  # coarse ZIP (first 3)

min_k <- function(df, cols) {
  df %>% count(across(all_of(cols))) %>% pull(n) %>% min()
}

cat("Using exact age as a quasi-identifier:\n")

qi$age_band <- cut(qi$age, breaks = c(0, 40, 65, 120), labels = c("<40", "40-64", "65+"))

9.5 Synthetic data and governance

The safest way to share is often not to share real records at all but a synthetic dataset that preserves statistical structure without mapping to real people — exactly what this series’ generator does.

Beyond technical methods, health data use sits inside a governance framework:

  • IRB approval for human-subjects research
  • Data Use Agreements (DUAs) governing what a recipient may do
  • Minimum necessary — access only the data required for the purpose
  • Limited Data Sets — a middle ground retaining dates/geography under a DUA

Production de-identification tools worth knowing: Microsoft Presidio, Philter, and NLM Scrubber. Formal privacy guarantees come from differential privacy.

Key takeaways

  • HIPAA offers two paths: Safe Harbor (remove 18 identifiers) and Expert Determination.
  • Structured de-id = suppress / generalize / pseudonymize; free-text de-id needs regex + name/place matching together.
  • k-anonymity guards against quasi-identifier re-identification.
  • Synthetic data and governance (IRB, DUA, minimum necessary) complete the picture.
